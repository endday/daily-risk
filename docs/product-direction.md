## 一、核心结论：产品定位是"决策陪伴器"

### 1.1 定位收敛过程

本文档经历了三轮不同视角的分析，最终收敛到一个产品定位结论。完整记录过程，便于后续追溯每个判断的依据：

| 轮次 | 视角 | 核心主张 | 问题 |
|------|------|----------|------|
| 第一轮 | 专业/变现 | 信息架构去重 + 回测页 + 订阅变现 + 券商导流 | 太"产品经理/投资人"视角，一上来就讲漏斗和变现，但产品还没有流量基础 |
| 第二轮 | 传播 | 判词升级 + 每日签 + 多空阵营 + 反向打脸指数 | 传播力强，但部分点子（多空阵营、竞猜盘口）偏向娱乐化，偏离"有参考价值"的初衷 |
| 第三轮 | 情绪陪伴 | 输出话术重构 + 视觉温柔化 + 事后回看 | **收敛点**：用户做"我想买/我想卖"按钮的真实动机是情绪价值，不是预测准确度 |

### 1.2 三种工具定位的对比

| 定位 | 逻辑 | 责任归属 | 代表产品 | 是否适合本项目 |
|------|------|----------|----------|----------------|
| 预测工具 | "我告诉你买不买" | 责任在工具，错了用户怪你 | 多数荐股/信号类产品 | ❌ 错一次信任崩塌 |
| 传播型产品 | 社交货币驱动，晒图传播 | 无明确责任 | 星座运势、每日签 | ⚠️ 偏娱乐，偏离参考价值 |
| **决策陪伴器** | "你已经决定了，我让你安心" | 永远是支持方，不错 | 老黄历 | ✅ **本项目定位** |

### 1.3 结论

本项目的核心定位是 **决策陪伴器**：用户在按下买入/卖出键的那一刻，缺的不是数据，是**勇气和底气**。产品的任务是给这个临门一脚的支持，而不是替用户做预测。

关键认知：**理性论证 ≠ 情绪支撑**。一个用户点完"我想买"，他要的是"你眼光没错"，不是"注意T+1锁仓风险"。

## 二、产品现状盘点（专业视角）

### 2.1 竞品定位分析

| 品类 | 代表产品 | 他们做 | 他们不做 |
|------|----------|--------|----------|
| 宏观事件日历 | 金十数据、华尔街见闻、Investing.com | 事件提醒 + 前值 + 预期值 | ❌ 不做 A 股日历效应统计 |
| 季节性/日历效应 | Stock Trader's Almanac（海外） | 历史涨跌概率统计 | ❌ 海外为主，A股覆盖薄 |
| 量化/策略 | 选股宝、果仁、聚宽 | 策略回测 | ❌ 不做"今天该不该买"这种轻决策 |

**差异化壁垒**：A 股三指数 20 年日历效应数据（`calendar-effects.json` 约 8100 行）+ 特殊窗口（春节/两会/财报季）+ T+1 决策算法（`decision.ts`）。这部分数据是别人没有、且需要时间积累的。

**定位弱点**：夹在"资讯工具"和"决策工具"中间，用户心智模糊。打开金十的人想看新闻，打开量化软件的人想回测，本产品的用户"到底为什么打开"需要被明确回答——答案是"为了在决定买卖那一刻获得支持"。

### 2.2 前端信息架构问题

前端是单页应用 + 底部 3 Tab（概览 / 事件 / 统计），但 Tab 之间的内容边界模糊：

- **概览 Tab**：研判 + 决策面板 + 双栏数据 + 今日要事 + 日历热力图，什么都往里塞。决策激活时（`v-if="!decisionActive"`）还要把其他内容全部隐藏，体验割裂。
- **事件 Tab**：顶部又重复了一遍短线/波段信号（和概览重复），然后才是事件列表。用户来看事件，却先看到一堆信号。
- **统计 Tab**：信息量最大、最专业，但被折叠隐藏，新手根本看不到核心壁垒。

### 2.3 重复清单（同一组数据多处展示）

| # | 重复内容 | 出现位置 | 次数 |
|---|----------|----------|------|
| 1 | 短线评分 + 操作信号 | 概览 headline、概览双栏"短线"列、事件 Tab 摘要、统计 Tab 黄历卡片短线维度 | **4 处** |
| 2 | 波段评分 + 操作信号 | 概览双栏"波段"列、事件 Tab 摘要、统计 Tab 黄历卡片波段维度 | 3 处 |
| 3 | 综合研判 advice 文案 | 概览 + 黄历卡片（字字相同） | 2 处 |
| 4 | 月度日历热力图 | 概览（compact）+ 统计（完整），同一组件两种模式 | 2 处 |
| 5 | 事件列表 | 概览"今日要事"（取前 2 条）+ 事件 Tab 完整列表 | 概览是子集 |

### 2.4 后端性能隐患

- **`computeAlmanac` 单次请求被调用 4 次**（1 次主黄历 + 3 次分指数黄历），其中**上证指数的黄历算了 2 遍**（`calendar.ts:306` 主路径 + `calendar.ts:446` 分指数路径），用了两套独立的代码计算同一份数据，是维护隐患。
- 周查询 `?week=` 模式会触发 **7 天 × 4 次 = 28 次** `computeAlmanac` 调用。
- 两个"预留接口"（`?week=`、`?range=today_tomorrow`）前端根本没用，是死代码（`index.ts:114, 139` 注释明确说明"预留接口，前端当前未使用"）。
- `/admin/recompute-calendar` 是 stub（`index.ts:304-310`），日历数据只能离线脚本更新，无法在线重算。

## 三、传播视角的五个放大方向

这五个方向来自第二轮传播视角的分析。传播力强，但需结合第四节"情绪陪伴"定位判断取舍——部分点子（如多空阵营）偏娱乐化，不一定符合最终定位，但作为完整记录保留。

### 3.1 判词升级

| 维度 | 内容 |
|------|------|
| 做什么 | 把信号 `add/hold/reduce` → 老黄历话术"宜/忌/慎" |
| 传播逻辑 | 让结论可被一句话复述。现在"短线评分6.2，宜观望"没法转述；"今日宜空仓，财运偏弱"才能被复述 |
| 成本 | 低（改文案） |

### 3.2 每日签

| 维度 | 内容 |
|------|------|
| 做什么 | 抽签 + 生成可保存的运势卡，把数据装进"可晒容器" |
| 传播逻辑 | 仿照支付宝年度账单、网易云年度听歌、星盘日运。产品有数据底座（别人抄不走），但缺一个"值得晒的容器"，每日签就是那个容器 |
| 成本 | 中（需设计投入） |

版面示例：

```
┌─────────────────────────┐
│  📅 6月15日 周日          │
│  明日 A 股运势            │
│                          │
│  【宜】轻仓试探           │
│  【忌】满仓追涨           │
│                          │
│  历史同日上涨概率 58%     │
│  近20年样本 n=18          │
│                          │
│  "行情在犹豫中生长"       │
│                          │
│  —— 来自明日风险榜        │
└─────────────────────────┘
```

### 3.3 多空阵营

| 维度 | 内容 |
|------|------|
| 做什么 | 买/卖按钮 → 加入阵营 + 多空比盘口（"今日多空比 58% : 42%"实时条） |
| 传播逻辑 | 群体归属 + 竞猜传播。博彩/竞猜 APP 验证过无数次的传播机制，套到 A 股情绪工具上 |
| 成本 | 中（需后端） |
| 取舍 | ⚠️ 偏娱乐化，偏离"参考价值"初衷，**与陪伴器定位有张力，暂缓** |

### 3.4 反向指标

| 维度 | 内容 |
|------|------|
| 做什么 | 自曝历史胜率 / 打脸指数（"本站过去30天，建议买入的日子，次日实际胜率62%"） |
| 传播逻辑 | 把社区梗产品化，反差出圈。A 股圈最爱的梗就是"反向操作""主力盯着我账户"。主动自曝其短反而建立信任，比吹自己准有用得多 |
| 成本 | 低（有现成数据） |
| 取舍 | ⚠️ 传播力强，但"打脸"叙事与陪伴器定位有张力。可改造为"成绩单"正向呈现（见 4.2） |

### 3.5 话术梗化

| 维度 | 内容 |
|------|------|
| 做什么 | 重命名 + 土味权威话术（"今日财运偏弱，宜观望，主力在洗盘"） |
| 传播逻辑 | 降低传播摩擦力。散户爱听、爱转这种话术 |
| 成本 | 低 |

### 3.6 五项归类总表

| 方向 | 传播逻辑 | 成本 | 与陪伴器定位契合度 |
|------|----------|------|--------------------|
| 判词升级 | 结论可复述 | 低 | ✅ 高（可并入话术重构） |
| 每日签 | 可晒容器 | 中 | ⚠️ 中（需设计，排在话术重构后） |
| 多空阵营 | 群体竞猜 | 中 | ❌ 低（娱乐化，暂缓） |
| 反向指标 | 梗化出圈 | 低 | ⚠️ 中（改造为正向成绩单） |
| 话术梗化 | 降低摩擦 | 低 | ✅ 高（可并入话术重构） |

**传播闭环**：每日签（抽签 → 晒图）+ 反向打脸（"这玩意儿还公开胜率？我也试试"）能形成传播闭环。但需结合第四节定位判断：现阶段先做话术重构验证陪伴价值，传播型功能排在后面。

## 四、情绪陪伴视角：现有实现的问题与重构

### 4.1 现有实现正在破坏情绪

`decision.ts` 的 `generateCaveats` 函数，用户点完"我想买"后，会给他看这些内容：

| 现有 caveat 文案 | 触发条件 | 对"刚决定买入的用户"的情绪影响 |
|------------------|----------|-------------------------------|
| "次日仍有 40% 概率下跌，T+1 锁仓风险" | `downProb > 0.3` | ❌ 泼冷水，强化焦虑 |
| "近期市场波动较大，注意控制仓位" | `maxVolatility > 0.01` | ❌ 泼冷水 |
| "A 股 T+1，买入当天无法卖出，需承受隔夜风险" | buy 固定 | ❌ 教科书式说教，用户都知道 |
| "次日仍有 45% 上涨概率，卖出可能踏空" | sell 且 `nextProb > 0.45` | ❌ 制造"万一卖错了"的后悔 |
| "历史统计基于近20年数据，不代表未来表现" | 固定 | ⚠️ 免责声明，必要但语气生硬 |

**结论**：用户点"我想买"的那一刻，他要的是临门一脚的勇气，当前实现给了三盆冷水。看完反而更纠结——这不是"让用户觉得决策没问题"，是"让用户觉得到处都是问题"。

### 4.2 话术重构方向

输出重心从"理性论证"挪到"情绪支撑"，三段式结构：

**① 主结论（定心丸）**
- 格式：✅ 绿色大字，敢下结论
- buy 示例：`✅ 数据支持你买入`
- sell 示例：`✅ 今天离场是对的`

**② 正向支撑（2-3 条）**
- 只保留正向论据，去掉恐吓式 caveat
- 核心话术模板：**"你的判断和近20年数据是一致的"** —— 这句话是关键，它在说"不是你冲动，是你有依据"
- buy 示例：
  - `买入次日历史上涨概率 62%，T+1 获利概率偏大`
  - `近5年该窗口偏强，效应未衰减`
  - `样本充足（n=18），统计可信`

**③ 风险提示（底部一句话，不列清单）**
- 软化：从清单式 → 一句话带过
- 示例：`市场总有意外，控制好仓位就行`
- 免责声明保留但放到最不显眼位置

**语气转变**：从"投资顾问"语气，变成"朋友陪你做决定"的语气。

**改动范围**：集中在 `decision.ts` 的 `generateReasons`（强化正向）/ `generateCaveats`（大幅削减或改写），不改后端数据，不改决策算法本身。

### 4.3 视觉调性：从"风险警示"到"温柔肯定"

当前问题：评分 + badge 的理性感太重，第一眼不像"陪伴"，像"研报"。

```
【当前样式：风险警示感】          【目标样式：温柔肯定感】
┌──────────────────────┐        ┌──────────────────────────┐
│ 短线评分 6.2          │        │                          │
│ [宜观望] (橙色 badge) │        │      ✅                  │
│ 上涨概率 58%          │        │                          │
│ 样本 n=18             │        │   数据支持你买入          │
│                      │        │                          │
│ ⚠ 次日40%概率下跌     │        │  你的判断和近20年数据一致  │
│ ⚠ T+1锁仓风险        │        │                          │
│ ⚠ 波动较大注意仓位    │        │  · 次日上涨概率 62%       │
└──────────────────────┘        │  · 近5年该窗口偏强        │
                                 │                          │
                                 │  市场总有意外，控制仓位就行 │
                                 └──────────────────────────┘
   密集数字 + 橙色警示              留白 + 绿色✅ + 大字结论
```

关键变化：
- 主结论用绿色 ✅、大字、留白
- 弱化数字密度（概率/样本数作为支撑小字）
- 风险提示压缩到底部一句话

### 4.4 事后回看闭环

光事前肯定还不够，**最强的"决策没问题"反馈，是事后告诉他"你看，你对了吧"**。

**机制**：
1. 用户点"我想买/我想卖" → 记录这个动作（localStorage，无需登录）
2. 几天后他再打开 → 顶部一行小字显示结果反馈

**两种结果的安抚话术**：

| 场景 | 话术 | 情绪作用 |
|------|------|----------|
| 赚了 | `3天前你想买入，如果那天动手了，现在 +3.2% 🎉 你眼光准` | 正向强化，"下次更敢决定" |
| 亏了 | `那天没动手是对的`（如果没记录实际操作）/ `市场总有意外，你的判断当时是有依据的` | 无论如何都有话术安抚 |
| 没动 | `3天前你犹豫了，后来涨了/跌了 X%` | 化解"没操作"的遗憾 |

**价值**：把一次性工具变成"每天想打开看看"，形成闭环：**决定 → 确认 → 验证 → 下次更敢决定**。

**技术要点**：
- localStorage schema：`{ date, intent: 'buy'|'sell', acted?: boolean, priceAtDecision?: number }`
- 回看时机：T+1（次日）/ T+3 / T+5，参考 A 股短线节奏
- 亏损话术边界：绝不指责用户，永远把锅推给"市场意外"，但保留"你的判断当时是有依据的"这种既安慰又不撒谎的措辞

## 五、新功能建议

### 5.1 低成本档（复用现有数据，建议优先）

| 功能 | 说明 | 价值 | 与陪伴器定位契合度 |
|------|------|------|--------------------|
| 历史回测/胜率验证 | 做"过去12个月，按本站信号操作的累计收益曲线" | 极高，直接提升信任 | ✅ 高（"成绩单"形式） |
| 事件影响复盘 | 事件发布 1/3/5 天后，标注市场实际走势 | 高，形成"预测→验证"闭环 | ✅ 高 |
| 指数/ETF 扩展 | 加创业板、科创50、北证50、主流行业 ETF 的日历效应 | 中，扩大覆盖面 | ✅ 中 |
| 每日推送 | 公众号/企微"明日风险早报" | 极高，获客+留存基建 | ✅ 高（陪伴触达） |

### 5.2 中高成本档（需新数据或用户系统）

| 功能 | 说明 |
|------|------|
| 持仓/自选股日历效应 | 用户输入持仓，自动算"你的持仓组合下周/下月胜率"，需用户系统，但是最强留存钩子 |
| 个股层面日历效应 | 现在是指数级，个股级需大量历史数据（Tushare/AKShare） |
| 市场预期 consensus | DESIGN V2 提过，需付费 API（FMP/Finnworlds） |
| 期货交割日/分红日 | DESIGN V1.5 提过，规则生成即可 |

## 六、盈利点建议

按现实程度排序。**前置判断**：纯工具型产品 + 没有用户系统 + 流量未知 = 现阶段直接收钱很难。以下路径需匹配产品阶段。

### 6.1 路径 1：券商开户导流（最现实）

- A 股用户和"要开户/换券商"高度重合，是 A 股内容/工具类产品最成熟的变现方式。
- 模式：操作信号或决策推荐附近放券商入口，按 CPA 拿返佣（一个有效户几十到几百元）。
- 本产品有"宜加仓/建议买入日期"这种离交易行为很近的场景，导流转化率比纯资讯站高。
- 门槛低，加个 H5 链接就能开始。

### 6.2 路径 2：Freemium 订阅（中期，需先建用户系统）

| 免费 | Pro（建议 ¥9.9/月 或 ¥88/年） |
|------|-------------------------------|
| 今日/明日风险指数 | **7 天风险预报**（`?week=` 接口已写好，未启用！） |
| 概览 + 事件 Tab | **历史回测曲线**（"按信号操作年化收益"） |
| 三大指数日历效应 | **更多指数/ETF + 个股自选** |
| 基础事件列表 | **事件复盘 + 市场预期值** |
| 手动查看 | **每日推送（公众号/企微）** |

定价一定要低（A 股散户对工具付费意愿弱，¥9.9/月是甜点价），靠量。

### 6.3 路径 3：公众号/小程序生态（获客 + 变现前置）

- 本产品内容（每日风险榜、特殊窗口解读、月度研判）天生适合公众号。
- 小程序版本作为公众号承载，推送卡片直跳小程序查看详情。
- 公众号粉丝 → 流量主广告 + 券商导流 + 知识星球/付费社群，是 A 股自媒体标准变现组合，比单做一个工具站健康得多。

### 6.4 路径 4：API 付费（长期，需数据护城河）

- 日历效应数据（20年 × 3指数 × 月度日度 + 特殊窗口）有价值，可做 API tier：免费 100 次/天，付费无限。
- 但这个体量，**除非数据做到全市场最全，否则很难单独成立**，只能作为补充。

### 6.5 路径 5：广告（兜底，不推荐为主）

- 移动端底部 Tab 栏上方加 banner 广告位。
- 工具类用户广告容忍度低，eCPM 不高，只能当零花钱。

### 6.6 分阶段建议

| 阶段 | 动作 |
|------|------|
| 现在（0→1 变现） | 加券商导流入口（最低成本、最快见效）+ 开公众号沉淀用户 |
| 接下来（建用户系统） | 加登录，把 `?week=` 接口启用成 Pro 功能，做历史回测页面 |
| 中期（订阅 + 推送） | Freemium 订阅 + 每日推送，跑通"免费工具 → 付费信号"漏斗 |

## 七、信号准确率与反向指标

### 7.0 实施分层：简化版优先，真版延后

> **v0.3 关键调整**：本节原方案的"最近 5/15/30 天实时胜率"需要新建历史日线表 + 信号快照表（详见 7.4），对单人项目是实质性的后端工程。经评审重新分层如下：

| 版本 | 数据来源 | 开发成本 | 上线时机 |
|------|----------|----------|----------|
| **简化版（近期做）** | 现成的日历效应历史涨跌概率（已有数据，零新增采集） | 🟢 低，纯前端 | 随话术重构一起做 |
| **真版（延后）** | 新建指数日线表 + 信号快照表（7.4） | 🔴 中高，需后端工程 | 待产品方向验证后再投入 |

**简化版的核心洞察**：每个信号背后本来就带着"历史上这种日子上涨概率 X%"。这个 X% 本身就是一种"准确率"表达——对散户来说，"历史上这种日子 62% 是涨的"比"最近30天对了18次"其实更好理解、更有说服力。**只要把这个概率从角落小字提到主结论旁边，配合诚实话术，就能零成本实现"准不准 + 倒逼独立思考"的效果。**

简化版的呈现（与第四节话术融合）：

| 概率区间 | 呈现 | 话术 |
|----------|------|------|
| ≥ 55% | 🟢 强化肯定 | `✅ 数据支持你买入 · 历史上这种日子 62% 是涨的` |
| 45% - 55% | 🟡 提示参考 | `⚠️ 信号偏中性 · 历史上这种日子涨跌各半，仅作参考` |
| < 45% | 🔴 提醒谨慎 | `⚠️ 历史上这种日子只有 42% 真涨——这次别急着动，你的犹豫可能是对的` |

**真版（7.1-7.6）保留为完整设计**，待简化版验证"诚实陪伴"被用户接受后，再投入做数据层。两者的关系：简化版是"历史概率"（静态统计），真版是"最近30天实时胜率"（动态成绩单），真版是简化版的增强而非替代。

### 7.1 功能定位：从"传播噱头"升级为"产品机制"

第三轮传播视角曾提出"反向打脸指数"（自曝历史胜率），当时判断为"传播力强但与陪伴器定位有张力，暂缓"。本节的需求将其从**偶发的传播噱头**升级为**常态化的产品机制**：

| 维度 | 旧的"反向打脸指数"（第三节 3.4） | 新的"信号准确率"（本节） |
|------|----------------------------------|--------------------------|
| 触发 | 偶发、用于造梗 | 常驻、每日更新 |
| 目的 | 传播出圈 | 让用户知道"这玩意儿最近灵不灵"，动态调整对信号的信任度 |
| 与陪伴器的关系 | 张力（打脸 = 否定） | **高度契合**：诚实告知 = 高级陪伴 |

**核心认知**：最高级的陪伴不是永远说"你对"，而是**诚实地告诉用户"最近数据准不准"**——准的时候给信心，不准的时候提醒"反着看"，这比盲目叫好更值得信任。用户要的是"被诚实对待"，不是"被哄着"。

### 7.2 功能描述

展示最近 5 / 15 / 30 天的信号准确率，并根据准确率动态调整对用户的引导话术：

**准确率定义**：在过去 N 天里，本站给出的"宜加仓/宜减仓"信号，如果按信号方向操作，次日实际涨跌方向与信号一致的占比。

| 准确率区间 | 产品呈现 | 引导话术 |
|-----------|----------|----------|
| ≥ 60% | 🟢 绿色"信号有效" | `最近30天准确率 65%，数据支持你的判断` |
| 50% - 60% | 🟡 黄色"参考使用" | `最近30天准确率 55%，仅作参考，结合自身判断` |
| < 50% | 🔴 红色"建议反向参考" | `最近30天准确率 42%，历史规律近期失效，**建议反着看**` |

**关键设计**：准确率不是简单的对错计数，而是要**让用户理解"什么时候准、什么时候不准"**。例如：
- 区分短线信号 vs 波段信号的准确率（两者可能差异很大）
- 标注"连续错 N 次"的预警（连续错 3 次时显著提示）
- 展示近期准确率趋势（是上升还是下降，反映日历效应的"有效期"）

### 7.3 与陪伴器话术的融合

这个功能与第四节的话术重构有天然衔接点：

| 场景 | 第四节话术（P0） | 加上准确率后（本节） |
|------|------------------|---------------------|
| 用户点"我想买"，准确率高 | `✅ 数据支持你买入` | `✅ 数据支持你买入，最近30天信号准确率65%` |
| 用户点"我想买"，准确率低 | （原方案会强行肯定）| `⚠️ 历史数据显示宜买入，但最近信号准确率仅42%，你的犹豫可能是对的——这次或许该再等等` |

**重要**：准确率低时的引导，**不是否定用户，而是"站在用户那边"提醒谨慎**。这才是陪伴器的诚实版本——不是无脑叫好，而是"好朋友会拦着你别冲动"。

### 7.4 技术可行性分析

#### 7.4.1 数据缺口：当前没有历史指数日线

要算准确率，需要 **"每日信号 vs 每日实际涨跌"** 的对照。现状盘点：

| 已有 | 缺失 |
|------|------|
| ✅ 每日信号（`calendar.ts` 的 `generateAlmanacSignal`，基于日历效应 rating） | ❌ 历史 30 天的指数日线收盘价 |
| ✅ 当日沪深300涨跌幅（`eastmoney.ts` 北向资金采集顺带抓了 `INDEX_CHANGE_RATE`，但只存最新一条 raw_json） | ❌ 信号历史快照（过去 N 天每天给的什么信号，没有落库） |
| ✅ 日历效应统计（`calendar-effects.json`，含历史涨跌聚合） | ❌ 三指数（上证/沪深300/中证500）的逐日实际值 |

**结论**：准确率功能的数据层需要从零搭建两块：①历史指数日线表，②每日信号快照表。

#### 7.4.2 数据源：东方财富 push2his 接口（免费可用）

经调研，东方财富历史 K 线接口可用：

```
http://push2his.eastmoney.com/api/qt/stock/kline/get
参数: secid=1.000300（沪深300，1=沪市前缀）, klt=101（日K）, fqt=0, beg=开始日期, end=结束日期, fields1/fields2=字段
```

- **免费、无需 API Key**，与现有 `eastmoney.ts` 采集器同一数据源，架构一致。
- ⚠️ 风险：多次高频调用易封 IP，需加请求间隔和 User-Agent。云函数场景建议**每日 cron 只拉一次增量**（拉过去 N 天，覆盖即可），不做高频轮询。
- 三指数代码：上证综指 `1.000001`、沪深300 `1.000300`、中证500 `1.000905`。

#### 7.4.3 信号快照：复用现有定时任务

现有 `scheduler.ts` 每日 22:00 cron 跑全量采集。可在同一 cron 中增加一步：

1. 采集当日三指数收盘价 → 写入 `index_daily` 表
2. 计算当日信号（复用 `getActiveCalendarEffects`）→ 连同日期写入 `signal_snapshot` 表

这样**每天积累一条**，30 天后即可算"最近30天准确率"。功能上线初期数据不足，可先回填：用 `getActiveCalendarEffects` 对过去 30 天批量重算信号（日历效应计算是纯函数，输入日期即可），配合新拉的 30 天日线，**首日即可上线准确率**。

#### 7.4.4 算法：信号对错判定

| 当日信号 | 次日实际涨跌 | 判定 |
|----------|-------------|------|
| `add`（宜加仓） | 上涨 | ✅ 对 |
| `add`（宜加仓） | 下跌 | ❌ 错 |
| `reduce`（宜减仓） | 上涨 | ❌ 错（减仓错过涨幅）|
| `reduce`（宜减仓） | 下跌 | ✅ 对（避开下跌）|
| `hold`（宜观望） | 任意 | ⚪ 不计入（中性信号不预测方向）|

**注意**：`hold` 信号不计入准确率分母，因为它本身不表态方向。这一点要在 UI 上说明，避免用户误解"为什么 hold 的日子不算"。

### 7.5 实施分层（建议）

| 阶段 | 内容 | 价值 |
|------|------|------|
| **MVP** | 仅沪深300 + 短线信号 + 30天准确率单值展示 | 验证"诚实陪伴"是否被用户接受 |
| **完整版** | 三指数 + 短线/波段双维度 + 5/15/30天切换 + 连错预警 + 趋势 | 数据驱动的动态信任调节 |
| **进阶** | 准确率趋势图、按市场环境（牛/熊/震荡）分桶统计 | 解释"什么时候准"，提升专业感 |

### 7.6 风险与边界

| 风险 | 应对 |
|------|------|
| 准确率长期偏低（<50%），用户流失 | 用"建议反着看"话术转化，反向指标本身也是产品特色（A 股社区梗）；同时复盘日历效应数据是否需要重新统计 |
| 样本不足（上线初期） | 用 7.4.3 的回填方案首日即有 30 天数据；UI 标注"基于历史回算" |
| 用户只盯准确率、忽视概率本质 | UI 强调"准确率是统计参考，非预测保证"，与免责声明联动 |
| 反向话术被滥用（用户每次都反着来，又错了） | 不提供"100% 反向跟单"的暗示，措辞始终是"建议反向**参考**"，保留不确定性 |

## 八、实施优先级与取舍

### 8.1 近期优先级：4 件"容易做且值得做"的事

> **v0.3 重新分级原则**：本节是面向"单人项目 + Cloudflare Worker + D1 + Vue 架构"的真实开发节奏。只列**纯前端、零新增数据源、零新表、零登录**的改动。所有依赖这些的工程统一移入 8.2"延后清单"。

**核心判断**：现阶段所有🔴级功能（回测、真·准确率、ETF扩展、持仓自选）**全部卡在同一个瓶颈——没有历史指数日线数据**。在投入搭建这个数据层之前，先把不依赖它的 4 件事做完，产品在"好看 + 让人安心"上就能有肉眼可见的提升。

| 优先级 | 事项 | 做什么 | 工作量 | 为什么值得 |
|--------|------|--------|--------|------------|
| **P0** | 话术重构 | `decision.ts` 的 `generateCaveats` 从泼三盆冷水改为正向肯定；风险提示软化为底部一句话 | 半天（单文件） | 情绪价值的命门——按钮做了，但点完让用户更纠结。改完立刻有感 |
| **P0** | 判词升级 | `display.ts` 把 `add/hold/reduce` → 老黄历"宜加仓/宜观望/宜减仓" | 1小时（一张映射表） | 让结论能被一句话复述，有记忆点和传播性 |
| **P1** | 信号准确率·简化版 | 把现成的"历史上这种日子上涨概率 X%"从角落小字提到主结论旁，配合 7.0 的三档话术 | 半天（复用现有数据，纯前端） | 零成本实现"诚实告知准不准 + 倒逼独立思考"，与 P0 话术同源 |
| **P1** | 去重 + 视觉温柔化 | 短线信号只在 1 处完整呈现（现重复 4 处），别处用"查看→"；主结论改 ✅绿色大字+留白 | 1-2 天（删+合并组件） | 减负不是加功能。信号只说一次力度才强；第一眼决定"好看" |

**4 件事总工作量约 3-4 天**，全部不碰后端和数据层。做完后产品的"陪伴感"和"好看度"会有明确变化，用于验证第四节的核心定位假设。

**执行顺序建议**：P0 两件先做（话术 + 判词，同源可一起改）→ P1 准确率简化版（复用 P0 话术框架）→ P1 去重视觉（结构清晰后再调样式）。

### 8.2 延后清单（现阶段不做，待产品验证后再投入）

> **不是永远不做，是现阶段不做**。这些功能要么依赖历史日线数据层，要么依赖用户系统，要么偏离陪伴定位。判断依据：先让产品本身值得被打开（8.1 的 4 件事），再投入做基础设施。

| 延后事项 | 卡点 | 触发条件（什么时候重新评估） |
|----------|------|------------------------------|
| **信号准确率·真版**（7.1-7.6 完整设计） | 需新建指数日线表 + 信号快照表 + push2his 采集器 | 简化版上线后，用户反馈"想知道最近准不准" |
| **回测/胜率验证页** | 需历史日线 + 策略引擎，与真·准确率共享数据层 | 有用户系统后，作为 Pro 功能 |
| **指数/ETF 扩展**（创业板/科创50/行业ETF） | 需新采集 + 重算日历效应，工作量与现有三指数持平 | 现有三指数数据被充分使用后 |
| **持仓/自选股日历效应** | 需登录 + 个股历史数据 | 用户系统建立后，最强留存钩子 |
| **每日推送/公众号** | 需公众号开发 + 持续运营 | 产品形态跑通后，作为获客基建 |
| **券商导流** | 技术门槛低，但需先有流量基础 | 有稳定 DAU 后 |
| **Freemium 订阅** | 需用户系统 + 多个 Pro 功能就位 | 真版准确率 + 回测页都上线后 |
| **多空阵营/竞猜盘口** | 需后端 + 偏娱乐化，偏离陪伴定位 | 若明确转向传播型产品 |

### 8.3 取舍说明（关键判断追溯）

记录分析过程中的关键判断，便于后续争论和修正：

1. ~~**"反向打脸指数"有传播力但暂缓**~~ → **已升级为产品机制（第七节）**：原 v0.1 判断为"与陪伴器定位有张力，暂缓"。v0.2 重新定位——从"偶发传播噱头"升级为"常驻诚实陪伴机制"。v0.3 进一步分层：简化版（现成历史概率）近期做，真版（实时胜率）延后。

2. **"每日签"虽好但排在话术重构之后**：传播闭环的关键容器，但需设计投入（视觉、文案、分享卡生成）。列入延后清单，待 P0/P1 验证陪伴价值后再做。

3. **"判词升级"和"话术梗化"并入 P0 话术重构**：第三轮的"肯定+共情"话术与第二轮的"宜/忌/慎"老黄历话术可融合——判词保持老黄历的画面感，但去掉恐吓，加肯定语气。

4. **`?week=` 死接口激活为 Pro 功能**：第一轮发现该接口已写好但前端未用，可作为 Freemium 的 Pro 功能（7天风险预报）。延后至用户系统建立后。

5. ~~**信息架构去重不进入近期优先级**~~ → **v0.3 纳入 P1**：去重本质是"删代码"，工作量小于加功能，且能立刻提升信息密度。从延后提升为近期 P1，与视觉温柔化一起做。

## 附：分析视角演进说明

本文档的三轮分析分别代表三种产品思考路径，各有价值但也各有盲区，完整保留以便后续评审时对照：

- **专业/变现视角**（第二节、第五节、第六节）：回答"产品有没有壁垒、能不能赚钱"。价值是看清护城河（数据底座）和变现天花板，盲点是忽视用户情感需求。
- **传播视角**（第三节）：回答"产品能不能被传播出去"。价值是找到社交货币和增长杠杆，盲点是可能滑向娱乐化、偏离参考价值。
- **情绪陪伴视角**（第四节、第七节、第八节）：回答"用户到底为什么打开、为什么留下"。这是最终的收敛点，因为它最贴近"我想买/我想卖"按钮的设计初衷。其中第七节"信号准确率"是陪伴视角的延伸——诚实告知"最近准不准"是陪伴的高级形态。

后续若产品方向调整（例如转向传播型或专业付费型），可基于本文档的不同章节重新组合优先级。
