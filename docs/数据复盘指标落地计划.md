# 数据复盘指标落地计划

## 目标

将 `docs/数据复盘2026-07-20.html` 中可复用的研究方法转化为 daily-risk 的结构性市场风险能力：

- 在已有市场温度之外，识别指数和风格的相对强弱；
- 用乖离、RSI、布林带和滚动收益差识别过热、超卖和风格切换；
- 所有信号保留历史样本、计算窗口和数据来源，避免把经验阈值伪装成预测结论。

## 一、需要先完成的数据统计

### P0：指数日线质量和基础收益

数据范围：`instrument_daily` 中已有的宽基指数。

优先指数：

- 上证指数 `000001`
- 沪深300 `000300`
- 中证500 `000905`
- 创业板指 `399006`
- 科创50 `000688`

先统计并校验：

- 每个指数的交易日数量、最早/最新日期；
- 收盘价缺失、重复日期、非正价格；
- 20、60、120、242、252 个交易日窗口的可用率；
- 20/60/120/252 日绝对收益；
- 最大回撤和 20 日历史波动率。

验收标准：窗口不足时返回 `null`，不能用不完整窗口伪造信号；所有指数使用同一交易日对齐规则。

### P0：指数相对强弱

对以下配对进行统计：

| 组合 | 解释 |
| --- | --- |
| 创业板指 / 沪深300 | 成长相对大盘蓝筹 |
| 科创50 / 创业板指 | 科技成长内部强弱 |
| 中证500 / 沪深300 | 中小盘相对大盘 |
| 沪深300 / 上证指数 | 蓝筹相对传统大盘 |

指标定义：

```text
log_relative_t = ln(close_A_t) - ln(close_B_t)
relative_return_N = exp(log_relative_t - log_relative_t-N) - 1
```

统计窗口：20、60、120、252 个交易日。

### P0：相对强弱的偏离和极值

对每个相对序列统计：

```text
log_bias_20 = (log_relative - EMA20(log_relative)) × 100
MA242 = mean(log_relative 最近242日)
STD242 = std(log_relative 最近242日)
zscore_242 = (log_relative - MA242) / STD242
```

再统计 RSI14：

```text
RSI14 = 100 - 100 / (1 + 平均上涨幅度14 / 平均下跌幅度14)
```

注意：`±2σ`、RSI 70/30 先作为状态标签，不能直接作为买卖信号。

### P1：风格切换的收益差

重点统计：

```text
spread_return_40 = return_A_40 - return_B_40
spread_return_252 = return_A_252 - return_B_252
```

需要回测：

- 40 日收益差处于历史前 5%/后 5% 后，未来 5、20、60 日的相对收益；
- 252 日收益差处于极值后，风格是否持续或反转；
- RSI 与收益差同时极端时，信号是否更可靠。

### P1：历史分位和信号表现

每个派生指标都应额外统计：

- 当前历史分位；
- 历史样本数量；
- 未来 5/20/60 日相对收益均值；
- 上涨概率；
- 最大有利/不利波动；
- 最近一次同类极值日期。

这一步用于验证经验阈值是否有实际信息量。

### P2：扩展宏观和跨市场数据

暂不作为第一阶段依赖，仅列入后续统计：

- 在岸/离岸人民币汇率及价差；
- 港股科技相对创业板；
- 黄金股相对黄金 ETF；
- 中信风格指数。

这些指标需要额外的数据源、代码映射和交易日历，不能与已有 A 股指数直接混用。

## 二、需要增加的功能

### P0：相对强弱计算模块

建议新增领域模块，例如：

```text
worker/src/domain/relative-strength.ts
```

输入对齐后的指数收盘价，输出：

- `relative_return_20d`
- `relative_return_60d`
- `relative_return_120d`
- `relative_return_252d`
- `log_bias_20_pct`
- `rsi_14`
- `zscore_242`
- `state`

计算模块必须是纯函数，便于 Vitest 直接覆盖边界和窗口不足场景。

### P0：相对强弱 API

建议新增正式接口，例如：

```text
GET /api/relative-strength?base=000300
```

响应至少包含：

- 当前交易日；
- 指数配对及名称；
- 各窗口收益差；
- RSI、乖离、Z-score；
- `normal / strong / overheated / weak / oversold` 状态；
- 数据覆盖天数和样本数。

不要把计算逻辑直接堆进 `worker/src/index.ts`。

### P0：前端“风格/相对强弱”视图

新增一个紧凑的结构性行情区域，优先展示：

- 当前最强和最弱的指数配对；
- 20 日、60 日、252 日相对收益；
- RSI14、242 日 Z-score；
- “趋势延续”或“相对极端”状态；
- 最近一次状态变化日期。

页面不直接输出“买入/卖出”，而是输出风险语义，例如“成长相对沪深300处于高位，追涨风险上升”。

### P1：市场温度中的结构性修饰项

在现有 `market-temperature` 结果之外增加结构性字段，避免覆盖已有绝对估值和流动性指标：

- `strongest_pair`
- `weakest_pair`
- `relative_extreme_count`
- `style_rotation_label`
- `relative_risk_score`

综合风险时，结构性风险只能作为修饰项，不能单独决定总风险指数。

### P1：历史回看和信号验证

增加一个可选的历史回看入口：

- 选择指数配对和指标；
- 查看历史极值点；
- 查看极值后 5/20/60 日实际表现；
- 显示样本数和失败案例。

这是将研究图表转成产品能力的关键，优先级高于增加更多指标。

### P1：测试和数据质量检查

新增测试覆盖：

- 不同指数交易日不完全重合；
- 缺失值、重复值和非正收盘价；
- 少于 14、20、242、252 个样本；
- RSI 全涨、全跌和无波动；
- 标准差为零；
- 相对收益和对数收益的数值一致性；
- API 对空数据和部分数据的返回。

## 三、推荐实施顺序

1. 先做指数日线质量统计和窗口覆盖报告。
2. 提取纯函数，完成相对收益、乖离、RSI、242 日 Z-score。
3. 为四组指数配对增加 API 和 Vitest。
4. 前端增加“风格/相对强弱”视图。
5. 用历史回测校准阈值，再决定是否影响总风险分数。
6. 最后再评估港股、汇率、黄金和风格指数扩展。

## 四、明确不做的事情

- 不直接复制文章中的图片或经验阈值作为交易策略；
- 不在第一阶段新增港股、黄金和风格指数数据源；
- 不把 RSI、布林带越界直接解释为必然反转；
- 不修改已有日历效应、估值和事件风险的计算口径；
- 不在没有历史验证前把相对强弱直接并入主风险指数。

## 五、完成定义

第一阶段完成的最低标准：

- 五个已有宽基指数有可验证的历史覆盖统计；
- 四组指数配对可计算 20/60/120/252 日相对收益；
- 每组配对有 RSI14、20 日乖离和 242 日 Z-score；
- API 返回窗口、样本数和状态标签；
- 前端可查看当前结构性强弱；
- 核心计算有单元测试，且不会因缺失数据产生假信号。
